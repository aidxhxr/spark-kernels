# spark-kernels

Hand-written CUDA kernels for LLM inference, built and benchmarked on an **NVIDIA DGX Spark**
(GB10 Grace Blackwell, compute capability 12.1, CUDA 13).

Every kernel is an *optimization ladder*: a naive version, then each step that removes a
bottleneck, benchmarked against cuBLAS or PyTorch and profiled with Nsight Compute. The point is
not to beat cuBLAS. The point is to show, with numbers, what each optimization buys on a real
Blackwell part with a 273 GB/s memory system.

> **Status:** kernels, benchmarks, PyTorch bindings, and tests are written. First build and
> benchmark run on the Spark is the next step; the results tables below are filled from
> `results/*.json` by `make results`.

## What is here

| Kernel | Ladder | Compared against | Bound by |
|---|---|---|---|
| `bandwidth_copy` | scalar → `float4` → grid-stride | `cudaMemcpy` D2D | DRAM (sets the roofline ceiling) |
| `rmsnorm` (+ fused `add_rmsnorm`) | thread/row → warp/row → 128-bit loads → block/row | PyTorch eager | DRAM |
| `swiglu` | scalar → 128-bit vectorized, fused `silu(g)*u` | PyTorch eager (2 kernels) | DRAM |
| `softmax` | 3-pass → warp online-softmax → block online-softmax | `torch.softmax` | DRAM |
| `sgemm` (fp32) | naive → smem tile → 8×8 register tile → cp.async double-buffer | cuBLAS SGEMM | FP32 cores |
| `hgemm` (bf16) | WMMA baseline → 128×128×32 smem tile, padded → cp.async pipeline | cuBLAS bf16 GemmEx | Tensor cores |

All kernels take a `variant` argument so every rung of the ladder is benchmarkable and
testable, and all are exposed to PyTorch through a C++ extension with parity tests.

## Why these kernels

They are the non-GEMM and GEMM building blocks of a Llama/Qwen decoder block, which is what I
serve in production with vLLM for [SwatGPT](https://github.com/aidxhxr/SwatGPT). On the GB10
the memory system is the constraint: 213 TFLOPS of bf16 tensor throughput against 273 GB/s
gives a ridge point of about 780 FLOP/byte, so every elementwise pass over activations is
expensive and fusion pays. `add_rmsnorm` and `swiglu` exist to make that concrete.

## Hardware

GB10: 48 SMs, 6,144 CUDA cores, ~2.42 GHz, 24 MB L2, 128 GB LPDDR5X unified memory at
273 GB/s, 5th-gen tensor cores. It is `sm_121`, the workstation Blackwell lineage: `mma.sync`
and `cp.async` work, `tcgen05` and TMA do not. Details in [docs/GB10.md](docs/GB10.md).

## Build and run (on the Spark)

Requirements: CUDA 13.0+, CMake 3.24+, a PyTorch build with `sm_121` support for the Python
bindings.

```bash
git clone https://github.com/aidxhxr/spark-kernels && cd spark-kernels

make build            # cmake configure + build, arch 121
make bench            # runs every bench_* binary, writes results/*.json
make results          # docs/RESULTS.md + results/roofline.png + results/headline.md

pip install -e . --no-build-isolation   # PyTorch extension, builds for sm_121 by default
pytest -q tests       # parity tests against torch for every variant
python scripts/bench_torch.py   # speedup vs PyTorch eager

make ncu              # Nsight Compute reports for hgemm and rmsnorm
```

Or run the whole sequence in one go with `./scripts/run_on_spark.sh`.

Individual benches accept overrides, for example:

```bash
./build/bench_hgemm --m=4096 --n=4096 --k=11008 --variant=2 --iters=200
./build/bench_rmsnorm --rows=8192 --cols=4096
```

Each bench validates every variant against a reference (CPU double precision or cuBLAS) and
exits non-zero on mismatch, so `make bench` doubles as the C++ test suite.

## Using the kernels from PyTorch

```python
import torch, spark_kernels as sk

x = torch.randn(4096, 4096, device="cuda", dtype=torch.bfloat16)
w = torch.ones(4096, device="cuda", dtype=torch.bfloat16)

y = sk.rmsnorm(x, w, eps=1e-6)            # fastest variant
y0 = sk.rmsnorm(x, w, eps=1e-6, variant=0) # naive, for comparison
out = sk.add_rmsnorm_(x, resid, w)         # fused residual add + norm, resid updated in place
h = sk.swiglu(gate, up)
p = sk.softmax(scores)
c = sk.hgemm(a_bf16, b_bf16)               # tensor-core GEMM
```

## Layout

```
include/spark/     public API (kernels.h) and shared device helpers (common.cuh)
src/kernels/       one .cu per kernel family, all variants inside
src/bench/         one bench binary per kernel, JSON-lines output
python/            PyTorch C++ extension and package
tests/             pytest parity tests for every variant
scripts/           bench runner, torch comparison, results tables, roofline, ncu
docs/              hardware sheet, design notes, generated results
```
